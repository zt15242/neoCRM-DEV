# 模型上下文管理

发送请求前，程序按模型配置估算系统提示、技能、对话、附件和工具定义的 token，并预留输出和安全空间。估算不是模型官方 tokenizer 计数；模型容量应以当前供应商或网关的实际限制为准。

接近预算时，先在本次请求副本中精简过长的工具结果；仍然超出时，已完成且有结果的较早工具调用，其大参数可被标记并精简，最近两次调用保留原样。原始会话和工具记录不会因此被修改。必要时，系统再对历史会话生成检查点，保留最近内容；摘要成功并核对会话未变后才保存检查点。

OpenAI 兼容接口和 Gemini 原生接口都会限制请求大小并维护工具调用与结果的配对。Gemini 原生接口收到明确的上下文超限错误时，仅在整理确实缩小请求后重试一次，不重复执行已完成工具。网络超时不会被误认作上下文超限。某次请求的最新内容、系统指令或工具定义本身过大时，自动整理可能仍然无法容纳；此时需要减少输入或使用经供应商确认的更大上下文模型。

自动摘要会丢失细节且需要模型调用，失败或取消不会删除原始历史或推进检查点。业务类型的技能在当前问题涉及该主题，或明确接续先前业务类型任务时自动加载；其他任务仍可按需调用相应技能。

当用户明确选择仅根据已有工具执行结果生成最终总结时，本次请求不附带工具定义，也不会调用工具；模型应区分已完成、失败和没有证据的事项。普通任务仍保留工具能力。这个处理不适用于同时要求修改、部署或执行新操作的请求。
