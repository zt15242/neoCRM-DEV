# 浏览器控制接入调研

参考项目：[DSH Browser Control](https://github.com/angelky7/dsh-browser-control)。该项目通过 Chrome 扩展、仅监听本机的 WebSocket 桥和 Chrome DevTools Protocol 控制真实浏览器，可以沿用用户当前 Chrome 的登录状态。上游使用 AGPL-3.0，本项目为 MIT；本次独立实现，没有复制上游代码。

## 当前原型

在设置中心的“智能体引擎”点击“开启并配对”，加载 NeoCRM 浏览器助手，在扩展中粘贴一次配对码即可。配对码和端口在本机保存；正常重启桌面端后自动启动桥接并重连，无需重复配对。手动关闭浏览器控制后不会自动启动，重新开启仍使用原有配对码。配对码用于保护本机浏览器访问权限，不应分享给其他人。

NeoCRM 浏览器助手支持列出和操作可访问的跨来源内嵌框架，以及选择项目文件或会话附件。框架重新读取或导航后，旧元素引用失效。点击、输入和文件选择采用脚本触发，部分要求真实用户操作的网站可能拒绝。截图针对整个标签页，需要所选模型支持图像输入。不支持填写密码或由模型执行任意页面脚本。每次可选择一个文件，最大 50 MB；目标网站可能在选择文件后立即上传。文件会临时复制到本机私有目录，关闭浏览器控制时清理。网页内容、截图和输入内容可能发送给所选模型。

## 接入目标

工作区“工具”右侧的“浏览器预览”标签页会显示当前会话最近操作的浏览器标签页的只读截图，打开预览时约每三秒刷新；该预览不会把截图发送给模型。NeoCRM 浏览器助手只能截取当前活动标签页，目标标签未激活时会提示。Agent 重复打开同一地址时优先复用当前会话已经使用的标签页；用户明确要求打开重复标签时可以新建。

浏览器助手 0.3.1 起声明持续截图所需的 `<all_urls>` 网站访问权限。升级已加载的扩展后，请在 Chrome 扩展管理页重新加载“NeoCRM 浏览器助手”，并确认网站访问权限为“在所有网站上”。若 Chrome 要求确认新增权限，需要用户完成确认；无需重新填写配对码。权限不足时预览会显示中文处理提示。截图前后均检查目标标签页，切换标签或导航时丢弃画面，下次刷新重试；仅允许普通 HTTP(S) 页面，不支持隐私窗口。

- 用户显式开启浏览器控制并完成扩展配对；连接状态和断开入口在设置中可见。
- Agent 能列出用户授权的标签页，打开网页、读取页面的可访问性快照、点击、输入、滚动和截图；图片需通过现有视觉模型路径传递。
- 标签页状态变化后重新获取元素引用；操作后读取页面状态，不能只依据点击成功就宣称业务完成。
- 根据会话模式与用户授权控制写操作；网页内容视为不可信数据，不能覆盖用户指令或授权。

## 安全边界

桥只监听回环地址，使用高强度随机配对令牌，校验连接来源和 Host；不能使用上游公开的默认令牌。需要明确连接生命周期、超时、断线重连及关闭行为。扩展应限制敏感浏览器页面和隐私模式，避免向模型暴露 Cookie、密码或身份凭据。文件上传必须限制用户授权的文件并核验真实路径，避免符号链接绕过。操作记录不应包含输入的机密信息。

## 尚需实现及验证

桥接协议的认证、恶意来源、取消和断开，以及模拟 Chrome API 的扩展通信已有自动化测试。已在真实 Chrome 的隔离测试页面验证 NeoCRM 浏览器助手的跨来源框架操作和文件传输；项目路径、附件和符号链接边界也有自动化测试。
